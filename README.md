# Mica Space / Mica空间

Mica Space 是 DSH 的可缩放对话地图插件：一条纵向主线，多条从回答分叉的支线，每个空间是一张独立画布。

长对话里，一个回答下面往往要继续追问很多次。传统聊天只能一直往下滚，想回到某个回答时又得上下翻找，文字一多就很难受。Mica Space 让每条追问直接从那张回答分叉：主线保持完整上下文，支线各自展开；后续回到主线时，本地记忆还能 callback 之前支线的结论。

## 功能

- 多空间、文件夹、子文件夹；
- 主线 / 支线 / 子支线树；
- 引用选中文字后继续追问；
- 图片和文件附件；
- 图片附件与扫描版 PDF 的本地 OCR（Tesseract，离线）；
- 回收站、撤销、搜索、整库导入导出；
- 卡片折叠、颜色、标签、待追问和红旗；
- 待追问卡片离开视口时的边缘 `!` 提醒；
- 横竖布局切换；
- 选中卡片后，Alt + 滚轮仍可缩放画布；
- 小卡片自动隐藏“待追问”文字，避免竖排；
- 分支颜色支持调色盘/十六进制输入；主线可单独设色；
- 分支说明默认折叠为“添加说明”；
- 切换工作区/重新进入空间保留原视角；
- 分支折叠/展开带堆叠卡片、淡入淡出和聚合标记；
- 支线卡四向连接点；
- 折叠点与展开点视觉区分；
- 追问框可收起，颜色选择为“更改颜色”文字 + 二级面板；
- 删除重复的“复制问答”；
- 重新问不移动视角，完成后显示蓝色未读标记；
- 横竖布局在创建空间时决定，之后不可切换；
- 定位原文会居中卡片，而不是居中文字片段；
- 已停止的回答旁边提供“重新问”。
- 本地记忆：主线摘要 + 分支摘要 + 父子级检索；
- 长回答自动分 chunk，命中子片段时回带父 turn；
- 零配置的轻量哈希向量，以及可选的本地共现语义模式；
- Git 备份（本地提交 + 可选私有 remote push）。

## 安装

Release 里的 `mica-space-0.99.3-demo.zip` 已包含运行依赖，解压后直接在 DSH 插件管理里选择该目录即可，不需要再执行 `npm install`。

源码安装仍然需要先 `npm install`。

1. 在 DSH 插件管理中安装本目录对应的插件包；
2. 确认侧边栏出现“Mica空间”；
3. 在 DSH 里配置一个聊天模型；
4. 新建空间，从第一个问题开始。

不需要用户另外安装：

- 向量数据库；
- embedding 模型；
- Python；
- embedding API。

## 两种记忆模式

在画布顶部点“记忆”切换：

### 轻量（默认）

- 关键词；
- 字符 n-gram 哈希向量；
- 零配置，速度最快。

### 本地语义增强

- 在当前空间的词语共现上构建分布语义向量；
- 零配置，不需要外部 API；
- 不是通用神经语义模型，不能理解任意同义改写；
- 每个空间独立构建，不共享其他用户数据。

## Agent 模式（v1.0 计划）

**当前的 0.99.3 demo 没有 Agent 模式。**

现在 Mica 里的每条对话都是一次普通模型调用：

- 发送系统提示词、历史消息、分支上下文、记忆和附件；
- 接收文字流；
- 不执行工具循环；
- 不读写文件，不运行命令，不调用 MCP，也没有 Agent 权限确认。

v1.0 会尝试把 Agent 模式接进来，但不会简单默认开启，也不会直接把现在的聊天全变成 Agent。计划中的方向是：

- 按空间或分支选择是否使用 Agent；
- 接入 DSH 的 Agent 会话和工具调用；
- 工具调用与权限确认以卡片形式挂到对应分支；
- 先做只读工具，再考虑写文件和执行命令；
- 明确分支复制、回到主线、中断后继续时 Agent 状态怎么处理。

Agent 模式涉及工具权限、会话持久化和分支语义，属于 v1.0 的探索项，不是 0.99.3 demo 的现有能力。

## 设置

- 使用说明、隐私、Git 备份、数据恢复、导入/导出；
- 界面语言跟随 DSH，不在 Mica 内单独切换；
- 中文欢迎文案读 `copy/welcome.json`，英文读 `copy/welcome.en.json`。

## 数据位置

默认工作区的：

```text
.chat-space/library.json
.chat-space/spaces/<id>.json
.chat-space/attachments/
.chat-space/trash/
```

每个空间独立保存，包含主线、分支、视图、memory。

## 隐私

- 轻量/本地语义模式不访问网络；
- 正常聊天时，问题、上下文和附件会发送给用户配置的 DSH 模型提供商；
- 文件抽取后的文本、图片 OCR 和 PDF OCR 结果也会进入聊天上下文；
- OCR 在本地完成，不上传图片或 PDF 到 OCR 服务；
- Git 备份只有用户主动配置 remote 并点击备份时才 push；
- 插件本身不包含遥测，不包含作者 API key。

## 已知限制

- 当前不是神经语义 RAG；
- PDF 文本层不足时自动本地 OCR，最多处理 8 页；OCR 质量受扫描清晰度影响；
- 新上传附件保存在 `.chat-space/attachments`；打开旧空间时会把 DSH 旧附件复制进来并改用本地引用；永久删除时清理本地文件；
- 附件文件不包含在导出 JSON 或 Git 备份里；
- 大空间已做视口裁剪，但未做完整的节点虚拟化；
- 核心测试覆盖上下文、空间库、embedding 和语义排序；另有 Playwright 真实浏览器 E2E；
- 当前版本为预览版，升级前请保留 `.chat-space` 备份；
- 0.99.3 demo 不包含 Agent 模式；Agent 计划在 v1.0 尝试。

## 测试

真实浏览器 E2E（Playwright + Chromium，加载插件 UI，mock Host API）：

